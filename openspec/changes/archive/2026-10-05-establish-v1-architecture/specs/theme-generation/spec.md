# Spec Delta

## Purpose

Defines how each album receives a unique, context-aware visual identity generated by AI, and the automated acceptance checks that make that artwork safe to print without human review.

## ADDED Requirements

### Requirement: Theme brief is inferred from trip context
The system SHALL derive a theme brief from country, region, cities, dates (season), event type, optional user notes and optional style preference. The brief SHALL contain: a palette of named colours, a short list of destination and season motifs, a mood description and texture words. The brief SHALL be stored with the album.

#### Scenario: Japan in January
- **WHEN** the trip is Kyushu with dates in January
- **THEN** the brief contains winter-appropriate motifs and palette and does not contain spring blossom motifs

### Requirement: Artwork is generated per album and never reused
For each album the system SHALL generate three spread backgrounds (A, B, C) and one front cover artwork from the brief. Generated artwork SHALL NOT be cached or served to another album.

#### Scenario: Two albums, same destination
- **WHEN** two different users create Kyushu albums in the same season
- **THEN** each receives artwork generated from its own request and the image files differ

### Requirement: Consistency across the set
The three backgrounds and the cover artwork SHALL share one style definition (palette, texture, illustration style, base tone) and SHALL differ in motif choice and placement. Where the model supports it, the same style conditioning SHALL be applied to all four generations.

#### Scenario: Variation without drift
- **WHEN** backgrounds A, B and C are compared
- **THEN** their mean colour and base luminance are within the configured tolerance of each other while their motif positions differ

### Requirement: Artwork constraints
Generated artwork SHALL satisfy: light base tone with high mean luminance so photos remain dominant, low local contrast, large quiet areas where photos will sit, no lettering or glyphs of any script, no people, no recognisable copyrighted characters. Backgrounds SHALL have a 2:1 aspect; cover artwork SHALL be oversized enough to be cropped for either binding and any spine width.

#### Scenario: Prompt forbids text
- **WHEN** a background request is composed
- **THEN** it includes an explicit instruction excluding any text, lettering, characters, stamps with writing or signage

### Requirement: Print resolution
Artwork SHALL be delivered at the pixel dimensions required for 300 dpi at the spread size including bleed (approximately 5030 x 2550 px for a 420 x 210 mm spread with 3 mm bleed). When the model cannot produce that size directly the system SHALL upscale the result.

#### Scenario: Upscaled output size
- **WHEN** the model returns a 2048 x 1024 image
- **THEN** the stored print asset is at least the required dimensions and the preview asset is a downscaled copy

### Requirement: Automated acceptance checks
Before any generated asset is shown or used, the system SHALL check: final dimensions and aspect, mean luminance above the floor, local contrast below the ceiling, palette within tolerance of the brief, and absence of readable text via an automated text detector. An asset failing any check SHALL be regenerated with the same brief.

#### Scenario: Dark background rejected
- **WHEN** a generated background's mean luminance is below the floor
- **THEN** it is discarded and a new generation is requested without user action

### Requirement: Fallback after repeated failure
After a configurable number of failed generations for one asset (initially 3), the system SHALL substitute a neutral paper background in the brief's palette for that asset so that the album can proceed, and SHALL record the substitution on the album.

#### Scenario: Order never blocks on artwork
- **WHEN** background C fails checks three times
- **THEN** the album uses the neutral fallback for C and the user can continue to preview

### Requirement: Artwork contains no customer content
Theme generation SHALL receive only the theme brief. It SHALL NOT receive customer photographs, thumbnails or per-photo metadata.

#### Scenario: Generation request payload
- **WHEN** an artwork request is sent
- **THEN** it contains the brief text and style parameters only

### Requirement: Artwork storage
Generated assets SHALL be stored server-side under the album, in print and preview sizes, and SHALL be retained for the album's lifetime so that reprints and re-renders use identical artwork.

#### Scenario: Reprint uses same artwork
- **WHEN** an album is re-rendered a month later
- **THEN** the identical background and cover assets are used

### Requirement: Model is replaceable
The image and text models used for theme generation SHALL be behind a single interface so that a different model can be used without changing the brief format, checks or storage.

#### Scenario: Model swap
- **WHEN** the configured image model is changed
- **THEN** the brief, checks and asset layout are unchanged and existing albums keep their assets
